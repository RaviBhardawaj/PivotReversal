# Changes, 7 Oct 2026 (Options-angel_live-ok.py)

Backup of the originals: `LiveOptionChain/_backup_20261007/` (code + old forward-test and paper-order CSVs).
Full diff: `notes/changes_20261007.diff`.

## Only 15M and 1H setups
- Entries and forward-test records happen only on strikes picked from 15M or 1H pivots (labels "15M Intraday", "1H Structure", "15M / 1H").
- "5M Dynamic" trades, the nearby Daily/Weekly/plan strikes, and the 5-Min level row (it was a copy of 15M) are removed from trading, the GUI filter and the sheet filter.

## WebSocket subscribes only pivot strikes
- `FeedEngine.prepare`: instruments = CE + PE at 15M R1/R2/S1/S2 and 1H R1/R2/S1/S2 snapped to the strike step, plus the spot index. No ATM ± N band. ATM band is used only if no pivots could be loaded at all (logged as a warning).
- If the app stays running into a new day, the new day's strikes are subscribed automatically.

## Levels locked during the live market
- 15M/1H index levels keep the existing formula (15M = last 25 completed 15-min bars, 1H = last 35 completed 1-hour bars), but bars from today's live session are excluded before 15:30. So the levels are identical whenever the app is started that day.
- Cache is now tied to the date; during 09:15–15:30 a cached set is never recalculated, even by the "refresh"/planner buttons. The 09:16 re-calculation is removed.
- Fixed: the old cache had no date check, so levels could carry over from earlier days. Yahoo bars are now kept aligned (the old code dropped empty values per column, which could misalign high/low/close). Weekly now always uses the last completed week.
- Option strike levels: before 15:30 they come from each option's previous completed daily candle (Angel `getCandleData`), not today's running high/low. During the session existing strike levels are never overwritten, and a strike without a level is skipped instead of computed from intraday data.

## Forward test
- Old data cleared: `forward_test_trades.csv` and `live_orders_log.csv` reset to headers only.
- Google Sheet "Forward Test" tab: rows below the current grid are wiped, so old trades don't linger.
- Trades left ACTIVE by a previous run are marked ABANDONED at start-up instead of staying open forever.
- The CSV is still written, because it is what the sheet is rebuilt from after a restart.

## WebSocket stability
- Each socket's callbacks are ignored once it has been replaced. Before, a late "closed" event from the old socket tore down the new one: a reconnect storm.
- Error and close events now collapse into one reconnect, with back-off 2s → 30s. Every 3rd failed attempt re-logs in to Angel One (expired token).
- Watchdog: in market hours it reconnects after 30s with no ticks; outside market hours it reconnects only if the heartbeat is dead. Before, it reconnected every 25s all evening.

## Tested here (stubbed broker and Yahoo)
- Levels identical at 09:00, 11:00, 11:00 with force refresh, and 14:59; they change only after 15:30.
- One drop → exactly one reconnect; a stale close does not kill the new socket; no reconnects after hours; a stalled feed in session reconnects once.
- `prepare` subscribes exactly the 15M + 1H focus strikes.

Not tested against the live Angel One / Google APIs from here.

# Round 2 (7 Oct, evening)

## P-level strike added
- 15M and 1H strike selection now includes the strike nearest the pivot P (`P_STRIKE`). It is traded on both CE and PE, with the same reversal state machine on that option's own levels.
- Traded and subscribed set per timeframe: R1, R2 (CE side), P (CE + PE), S1, S2 (PE side).
- The strike mapper now fetches levels only for these traded strikes (R3/S3 strikes dropped).

## Websocket and dashboard keep running
- **Dashboard freeze (root cause):** every status update (about every 2s) started a new 300 ms refresh loop. After an hour thousands of loops flooded Tk, so the window froze or stopped opening. Now exactly one refresh loop runs, and a display error can't kill it.
- Background threads no longer touch Tk directly. Their `root.after` calls go through a queue that the main thread drains (macOS Tk is not thread-safe).
- **Freeze watchdog:** if the window is frozen for 120s the app exits with code 3, and the launcher restarts it.
- **Auto-restart:** `run_option_chain.command` and `run.sh` now relaunch the app after a crash or freeze and resume the feed on the last symbol (`last_session.json`). Closing the window normally ends it.
- **Mac stays awake:** the app runs under `caffeinate`, and App Nap is disabled for Python, so sleep can't stall the websocket.
- One bad tick can no longer close the websocket. Google Sheets calls time out after 20s instead of hanging the feed loop.

## Forward test in Google Sheet
- **Wrong exits fixed:** a tick from another expiry of the same strike was updating the trade. This caused fake instant "Target 5 Hit" and "SL Hit" exits, and was most of the same-second exits seen in the old data.
- **New columns:** "HH After Entry" and "LL After Entry". The Status column shows the live SL and T1, or which target was hit and where the SL trailed to.
- The sheet is written immediately on every entry and exit. On first sync the tab is cleared below the grid, so the old data disappears.
- **3 PM:** open trades are closed at LTP at 15:00 if SL or target wasn't hit (already in the code, now tested).
- The sheet shows today's trades; earlier days stay in `forward_test_trades.csv`.
